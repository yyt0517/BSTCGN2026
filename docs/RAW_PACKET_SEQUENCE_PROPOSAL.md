# 原始包序列分类方案 - 技术提案

## 📋 执行摘要

当前LightGBM模型在聚合特征上达到了95.17% Macro F1，但STGNN等时序模型只有70%左右。**核心原因**是数据已经被聚合成统计特征，丢失了细粒度的时序信息。

本提案提出**直接使用原始包级别的时序数据**，配合Transformer模型，有望突破95%的性能上限。

---

## 🎯 问题分析

### 当前方案的局限性

**数据处理流程**：
```
原始PCAP包流 (数百万个包)
    ↓ 1秒窗口聚合
统计特征 (avg, std, count等) - 22,822条记录
    ↓ 5秒窗口滑动
序列数据 (8,717个序列)
    ↓ 模型训练
LightGBM: 95.17% ✓
STGNN: 70.59% ✗
```

**信息损失**：
1. **时间精度损失**: 1秒窗口内的包到达顺序丢失
2. **微观模式损失**: 短时突发、包间隔等细节丢失
3. **协议交互损失**: TCP握手、重传等模式被平均化
4. **攻击特征损失**: 扫描的端口序列、洪泛的包模式等

### 为什么时序模型表现差？

| 模型 | Macro F1 | 原因 |
|------|----------|------|
| LightGBM | 95.17% | 擅长处理聚合统计特征 |
| XGBoost | 93.01% | 擅长处理聚合统计特征 |
| LSTM | 66.92% | 聚合后时序依赖性弱 |
| GRU | 67.81% | 聚合后时序依赖性弱 |
| STGNN | 70.59% | 图结构表达能力有限 |

**结论**: 不是模型不好，而是**数据不适合时序模型**！

---

## 💡 解决方案

### 核心思想

**使用原始包级别的时序数据**，让时序模型发挥真正的优势。

**新的数据处理流程**：
```
原始PCAP包流 (数百万个包)
    ↓ 提取每个包的特征
原始包序列 (每个包: 14维特征)
    ↓ 固定长度切分 (100个包/序列)
包序列数据 (数十万个序列)
    ↓ Transformer建模
预期性能: > 95% ?
```

### 关键优势

1. **保留完整时序信息**：
   - 每个包的精确时间戳
   - 包到达顺序
   - 包间隔时间

2. **捕捉微观模式**：
   - TCP三次握手
   - 端口扫描序列
   - 洪泛攻击的包模式
   - 慢速攻击的时间特征

3. **Transformer优势**：
   - 多头自注意力捕捉包之间的依赖
   - 位置编码保留时序信息
   - 并行计算，训练效率高

## 🏗️ 技术方案

### 1. 数据提取

**从PCAP提取14个包级别特征**：

| 特征 | 说明 | 攻击检测价值 |
|------|------|-------------|
| `timestamp` | 相对时间戳 | 包间隔、突发模式 |
| `packet_length` | 包长度 | 异常大小、洪泛模式 |
| `protocol` | 协议类型 | 协议分布、异常协议 |
| `src_port` | 源端口 | 扫描模式、异常端口 |
| `dst_port` | 目标端口 | 扫描目标、服务识别 |
| `tcp_flags_*` | TCP标志 | 握手模式、异常标志 |
| `tcp_window` | TCP窗口 | 流量控制、异常窗口 |
| `ttl` | 生存时间 | 伪造检测、路由跳数 |
| `payload_size` | 载荷大小 | 数据传输、异常载荷 |
| `ip_len` | IP包长度 | 分片检测、异常长度 |

**序列构造**：
- 序列长度: 100个包
- 滑动窗口: stride=50 (50%重叠)
- 预期序列数量: 数十万个

### 2. 模型架构

**PacketTransformer**：

```
Input: (batch, seq_len=100, features=14)
    ↓
Feature Embedding: Linear(14 → 128) + LayerNorm + ReLU
    ↓
Positional Encoding: 正弦/余弦位置编码
    ↓
Transformer Encoder: 4 layers, 8 heads, FFN=512
    ↓
Global Average Pooling: (batch, 128)
    ↓
Classifier: MLP(128 → 64 → 9)
    ↓
Output: (batch, 9 classes)
```

**参数量**: ~800K (比STGNN的156K大5倍)

**训练策略**：
- Loss: Focal Loss (处理类别不平衡)
- Optimizer: AdamW (weight_decay=0.01)
- Scheduler: ReduceLROnPlateau
- Batch size: 64
- Epochs: 100
- Early stopping: patience=20

### 3. 实验设计

**对比实验**：

| 实验 | 数据类型 | 模型 | 预期Macro F1 |
|------|---------|------|-------------|
| 基线1 | 聚合特征 | LightGBM | 95.17% (已完成) |
| 基线2 | 聚合特征 | STGNN | 70.59% (已完成) |
| **实验1** | **原始包序列** | **Transformer (基础)** | **85-90%?** |
| **实验2** | **原始包序列** | **Transformer (增强)** | **90-95%?** |
| **实验3** | **原始包序列** | **LSTM + Attention** | **80-85%?** |

**成功标准**：
- ✅ 优秀: Macro F1 > 95% (超越LightGBM)
- ✅ 良好: Macro F1 > 90% (接近LightGBM)
- ⚠️ 一般: Macro F1 > 80% (超越STGNN)
- ❌ 失败: Macro F1 < 80% (不如STGNN)

## 📊 预期结果分析

### 场景1: 成功 (Macro F1 > 95%)

**结论**: ✅ 原始包序列方案显著优于聚合特征！

**原因**:
- 细粒度时序信息至关重要
- Transformer成功捕捉了包之间的复杂依赖
- 微观攻击模式被有效学习

**影响**:
- 证明了时序模型的价值
- 为未来研究指明方向
- 可以发表高质量论文

**推荐**:
- 生产环境使用原始包序列 + Transformer
- 继续优化模型架构
- 探索更大规模的数据集

### 场景2: 接近 (Macro F1 = 90-95%)

**结论**: ⚖️ 原始包序列方案与聚合特征相当

**原因**:
- 聚合特征已经包含了大部分信息
- 原始包序列的额外信息贡献有限
- 模型可能还有优化空间

**影响**:
- 两种方案各有优劣
- 需要权衡性能和成本

**推荐**:
- 实时检测: 使用聚合特征 + LightGBM (更快)
- 离线分析: 使用原始包序列 + Transformer (更准)
- 继续优化Transformer模型

### 场景3: 失败 (Macro F1 < 80%)

**结论**: ❌ 原始包序列方案不如聚合特征

**可能原因**:
1. **模型容量不足**: 800K参数可能不够
2. **训练数据不足**: 需要更多包
3. **序列长度不合适**: 100个包可能太短或太长
4. **过拟合**: 模型记住了训练数据
5. **特征选择不当**: 14个特征可能不够

**改进方向**:
1. 增加模型容量 (d_model=256, num_layers=6)
2. 增加训练数据 (读取更多PCAP文件)
3. 调整序列长度 (50, 200, 500)
4. 添加更多特征 (IP地址、更多TCP选项)
5. 使用预训练模型
6. 数据增强 (时间扰动、包丢弃)
