# 50包实验优化总结

## 🎯 实验目标

将模型从100包改为50包，对比：
1. 检测性能是否相当
2. 推理速度是否更快
3. 与参考论文（GTAE-IDS: 2-8包，Graph2vec: 50包）对比

## 📊 关键发现

### 数据量爆炸问题

| 参数 | 100包 | 50包 | 变化 |
|------|-------|------|------|
| 序列长度 | 100 | 50 | -50% |
| 步长 | 50 | 25 | -50% |
| 训练样本 | 11,467 | 150,154 | **+1209%** |

**原因**：保持50%重叠率，步长也减半，导致数据量增加13倍！

### 计算复杂度分析

**单样本计算量**：
- Transformer: O(L²) = 100² → 50² = **减少75%**
- GNN: O(L²) = 100² → 50² = **减少75%**

**总训练时间**：
- 数据量：13倍增加
- 单样本：4倍减少
- **总计算量**：13 ÷ 4 = **3.25倍增加**

## 🚀 优化策略

### 1. 增大Batch Size

```python
# 优化前
BATCH_SIZE = 64

# 优化后
BATCH_SIZE = 128  # 训练
BATCH_SIZE = 256  # 验证/测试（无梯度，可以更大）
```

**效果**：提高GPU利用率，1.5-2倍加速

### 2. 混合精度训练（AMP）

```python
USE_AMP = True
scaler = torch.cuda.amp.GradScaler()

with torch.cuda.amp.autocast():
    logits = model(sequences)
    loss = criterion(logits, labels)
```

**效果**：FP16计算，1.3-1.5倍加速

### 3. 多进程数据加载

```python
DataLoader(
    dataset,
    batch_size=BATCH_SIZE,
    num_workers=2,  # 多进程
    pin_memory=True,  # 加速CPU->GPU传输
    persistent_workers=True  # 保持worker进程
)
```

**效果**：CPU预处理与GPU计算并行，1.2-1.5倍加速

### 4. 推理优化

```python
# 1. 更大batch size
inference_batch_size = 256

# 2. 无梯度计算
with torch.no_grad():
    logits = model(sequences)

# 3. 评估模式
model.eval()
```

**效果**：推理速度比训练快5-10倍

## 🔍 常见问题

### Q1: 为什么不直接截取前50包？

**问题**：
1. 浪费后50包数据
2. 破坏序列连续性

**正确做法**：从原始PCAP重新提取，使用滑动窗口

### Q2: 为什么训练变慢了？

**答**：数据量增加13倍是主要原因

虽然单样本计算快4倍，但数据量增加13倍，总计算量仍增加3.25倍。

**解决**：通过batch size、AMP、多进程等优化，最终训练时间与100包版本相当。

### Q3: 推理为什么更快？

**答**：
1. 序列短：O(50²) vs O(100²)，4倍加速
2. 无梯度：只有前向传播
3. 大batch：GPU利用率更高

### Q4: 与参考论文的区别？

**GTAE-IDS（2-8包）**：
- 网络拓扑图（节点=IP+端口）
- 无监督异常检测
- 二分类

**Graph2vec（50包）**：
- Burst图（5-20节点）
- 基于规则构图
- Random Forest分类

**我们的方法（50包）**：
- 包级图（50节点）
- 基于学习构图（KNN）
- 端到端神经网络
- 9类细粒度分类
