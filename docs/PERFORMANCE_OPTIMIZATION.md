## 🚀 优化策略

### 1. 增大Batch Size（最有效）

**原理**：GPU并行处理能力未充分利用

```python
# 优化前
BATCH_SIZE = 64

# 优化后
BATCH_SIZE = 128  # 训练时
BATCH_SIZE = 256  # 验证/测试时（无梯度计算，可以更大）
```

**预期加速**：1.5-2倍

### 2. 混合精度训练（AMP）

**原理**：使用FP16计算，减少内存占用和计算时间

```python
# 已启用
USE_AMP = True
scaler = torch.cuda.amp.GradScaler()

with torch.cuda.amp.autocast():
    logits = model(sequences)
    loss = criterion(logits, labels)
```

**预期加速**：1.3-1.5倍

### 3. 多进程数据加载

**原理**：CPU预处理数据，GPU计算时不等待

```python
# 优化前
num_workers=0  # 单进程

# 优化后
num_workers=2  # 多进程（Windows上2-4较稳定）
persistent_workers=True  # 保持worker进程，避免重复创建
```

**预期加速**：1.2-1.5倍

### 4. 优化图构建

**当前实现**：每个batch动态构建KNN图
- 复杂度：O(B × L² × H)
- 50包：O(B × 50² × 128) = O(B × 320,000)
- 100包：O(B × 100² × 128) = O(B × 1,280,000)

**优化效果**：50包的图构建开销是100包的**25%**

### 5. 减少序列长度的计算优势

| 操作 | 100包 | 50包 | 加速比 |
|------|-------|------|--------|
| Transformer自注意力 | O(L²) = 10,000 | O(L²) = 2,500 | **4倍** |
| GNN图卷积 | O(L²) = 10,000 | O(L²) = 2,500 | **4倍** |
| TCN卷积 | O(L) = 100 | O(L) = 50 | **2倍** |

**理论加速**：单个样本处理速度提升**3-4倍**

### 6. 推理优化

推理时无需梯度计算，可以进一步优化：

```python
# 1. 更大的batch size
inference_batch_size = 256  # vs 训练时的128

# 2. torch.no_grad()
with torch.no_grad():
    logits = model(sequences)

# 3. model.eval()
model.eval()  # 禁用dropout和batch norm的随机性

# 4. TorchScript编译（可选）
model = torch.jit.script(model)  # 编译为静态图
```

**预期推理速度**：比训练快**5-10倍**

## 🎯 为什么训练慢但推理快？

### 训练慢的原因

1. **数据量大**：150k样本 vs 11k样本（13倍）
2. **梯度计算**：反向传播开销
3. **优化器更新**：AdamW需要维护动量和二阶矩
4. **数据增强**：虽然我们没用，但一般训练会有
5. **多个epoch**：需要遍历数据集100次

### 推理快的原因

1. **无梯度计算**：只有前向传播
2. **序列短**：50包 vs 100包，计算量减少75%
3. **更大batch size**：GPU利用率更高
4. **无dropout**：减少随机性开销
5. **单次遍历**：只需要过一遍数据

## 🔍 性能监控

训练时应监控以下指标：

1. **GPU利用率**：应该>80%
2. **内存使用**：不应该OOM
3. **数据加载时间**：应该<计算时间
4. **每秒样本数**：应该>1000 samples/s

使用工具：
- `nvidia-smi`：监控GPU
- `torch.cuda.memory_summary()`：内存分析
- `torch.profiler`：性能分析
