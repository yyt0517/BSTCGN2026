# 性能优化分析与方案

## 当前性能指标

| 指标 | 值 | 评价 |
|------|-----|------|
| 测试准确率 | 96.87% | ✓ 优秀 |
| Macro F1 | 92.30% | ✓ 优秀 |
| 平均不确定性 | 0.4428 | ✓ 良好 |
| 训练时间 | ~90 epochs × 61s = 91分钟 | ⚠️ 可优化 |
| 验证时间/epoch | ~30s (8 MC采样) | ⚠️ 可优化 |

## 性能瓶颈分析

### 1. 验证阶段的MC采样 (最大瓶颈)

**问题**：
- 每个epoch验证使用8次MC采样
- 验证集32,176样本，batch_size=128 → 252个batch
- 每个batch需要8次前向传播
- 总计：252 × 8 = 2,016次前向传播/epoch

**时间成本**：
- 验证时间 ≈ 30秒/epoch
- 总验证时间 ≈ 90 × 30 = 45分钟 (占总训练时间50%)

### 2. 不确定性量化的计算复杂度

**问题**：
- 每次MC推理需要计算互信息
- 涉及对数运算和熵计算
- 对于大batch可能有数值稳定性问题

### 3. 模型架构的计算成本

**问题**：
- 3个贝叶斯ST块，每个都有采样操作
- 贝叶斯层的重参数化采样有额外开销
- KNN图构建虽然确定性，但仍需计算

## 优化方案

### 方案1: 自适应MC采样 (推荐)

**目标**：减少验证时的MC采样次数，同时保持性能

**实现**：
```python
# 验证阶段使用自适应采样
- 初始采样: 3次 (快速)
- 置信度阈值: 0.95
- 最大采样: 8次
- 预期减少: 50-70%的验证时间
```

**预期效果**：
- 验证时间: 30s → 10-15s
- 总训练时间: 91分钟 → 60-70分钟
- 性能影响: <0.5%

### 方案2: 验证频率调整

**目标**：减少验证次数

**实现**：
```python
# 前期(epoch 1-30): 每个epoch验证
# 中期(epoch 31-60): 每2个epoch验证
# 后期(epoch 61+): 每3个epoch验证
```

**预期效果**：
- 验证次数: 90 → 60
- 总训练时间: 91分钟 → 70分钟
- 性能影响: 可能错过最优点

### 方案3: 混合精度优化

**目标**：加速贝叶斯层的采样

**实现**：
```python
# 已启用AMP，但可进一步优化
- 使用float16进行MC采样
- 仅在最终聚合时使用float32
```

**预期效果**：
- 验证时间: 30s → 20s
- 性能影响: 可能有数值稳定性问题

### 方案4: 批量MC推理优化

**目标**：优化MC采样的内存访问模式

**实现**：
```python
# 当前: 逐次采样，每次都要加载模型权重
# 优化: 预先采样所有权重，然后批量前向传播
```

**预期效果**：
- 验证时间: 30s → 18s
- 性能影响: 无

## 不确定性量化的改进

### 当前问题

- 互信息计算涉及对数，可能有数值不稳定
- 不确定性与错误相关性: 0.1156 (可更高)

### 改进方案

1. **使用稳定的熵计算**
   ```python
   # 当前: -sum(p * log(p + 1e-10))
   # 改进: torch.special.entr(p).sum()
   ```

2. **多种不确定性度量**
   - 互信息 (当前)
   - 变分比率 (Variation Ratio)
   - 预测熵 (Predictive Entropy)
   - 集成方差 (Ensemble Variance)

3. **校准不确定性**
   - 使用验证集校准
   - 使用温度缩放

## 推荐优化路线

### 第一阶段 (快速收益)
1. 实现自适应MC采样 (预期: -40%验证时间)
2. 优化熵计算的数值稳定性

### 第二阶段 (中等收益)
3. 实现批量MC推理优化 (预期: -30%验证时间)
4. 添加多种不确定性度量

### 第三阶段 (长期优化)
5. 模型蒸馏 (将贝叶斯模型蒸馏到确定性模型)
6. 量化感知训练 (QAT)
