# 图结构常见问题解答（FAQ）

## Q1: 为什么有 100 个节点？数据不是只有 25 个特征吗？

**A**: 这是最常见的误解！

**节点数 ≠ 特征数**

- **100 个节点** = 100 个数据包（时间步）
- **25 个特征** = 每个数据包的特征维度

### 详细解释

数据形状：`(batch_size, seq_len, num_features) = (64, 100, 25)`

```
维度 0: batch_size = 64    → 64 个样本
维度 1: seq_len = 100       → 每个样本 100 个数据包（100 个节点）
维度 2: num_features = 25   → 每个数据包 25 个特征
```

### 可视化

```
样本 1:
  数据包 1 (节点 1): [特征1, 特征2, ..., 特征25]  ← 25维向量
  数据包 2 (节点 2): [特征1, 特征2, ..., 特征25]  ← 25维向量
  数据包 3 (节点 3): [特征1, 特征2, ..., 特征25]  ← 25维向量
  ...
  数据包 100 (节点 100): [特征1, 特征2, ..., 特征25]  ← 25维向量
  
  → 100 个节点，每个节点有 25 维特征
```

## Q2: 图的邻接矩阵是什么？

**A**: 邻接矩阵描述节点（数据包）之间的连接关系。

### 形状

- **单个样本**: `(100, 100)` - 100 个节点之间的连接
- **一个 batch**: `(64, 100, 100)` - 64 个图，每个图 100×100

### 含义

```
邻接矩阵 adj[i, j] = 1  表示节点 i 和节点 j 之间有边（连接）
邻接矩阵 adj[i, j] = 0  表示节点 i 和节点 j 之间无边
```

### 示例

```
     节点1  节点2  节点3  节点4  ...  节点100
节点1  [ 1     1     0     1    ...    0   ]
节点2  [ 1     1     1     0    ...    0   ]
节点3  [ 0     1     1     1    ...    1   ]
节点4  [ 1     0     1     1    ...    0   ]
...    [ ...  ...   ...   ...   ...   ... ]
节点100 [ 0     0     1     0    ...    1   ]
```

**解读**：
- `adj[1, 1] = 1`: 节点1 连接到自己（自环）
- `adj[1, 2] = 1`: 节点1 连接到节点2
- `adj[1, 3] = 0`: 节点1 不连接到节点3

## Q3: 边是如何构建的？

**A**: 使用 **K-近邻（KNN）** 算法，基于特征相似度。

### 步骤

1. **计算相似度**：计算任意两个节点（数据包）之间的余弦相似度
   ```python
   sim = torch.matmul(x_norm, x_norm.transpose(-1, -2))  # (100, 100)
   ```

2. **选择 Top-K 邻居**：每个节点选择最相似的 K=10 个邻居
   ```python
   _, indices = torch.topk(sim, k=10, dim=-1)  # (100, 10)
   ```

3. **构建邻接矩阵**：将选中的邻居标记为 1
   ```python
   adj = torch.zeros(100, 100)
   adj.scatter_(-1, indices, 1.0)
   ```

4. **对称化**：使图变为无向图
   ```python
   adj = (adj + adj.transpose(-1, -2)) / 2
   ```

5. **添加自环**：每个节点连接到自己
   ```python
   adj = adj + torch.eye(100)
   ```

### 结果

- 每个节点连接到 **~20 个邻居**（K=10，对称化后约翻倍）
- 图密度：**~10%**（远低于全连接的 100%）

## Q4: 为什么选择 K=10？

**A**: 平衡性能和计算效率。

### 不同 K 值的影响

| K | 边数 | 图密度 | 平均度数 | 计算量 | 性能 |
|---|------|--------|---------|--------|------|
| 5 | ~500 | 5% | ~10 | 低 | 中 |
| **10** | **~1,000** | **10%** | **~20** | **中** | **高** ✅ |
| 20 | ~2,000 | 20% | ~40 | 高 | 高 |
| 50 | ~5,000 | 50% | ~100 | 很高 | 中 |
| 99 | ~9,900 | 100% | ~198 | 极高 | 低 |

**选择 K=10 的原因**：
- ✅ 足够捕获局部结构（每个包连接到 10 个最相似的包）
- ✅ 计算效率高（图密度仅 10%）
- ✅ 实验验证性能最佳

## Q5: 图是静态的还是动态的？

**A**: **动态图** - 每个 batch 重新构建。

### 动态 vs 静态

| 类型 | 构建方式 | 优点 | 缺点 |
|------|---------|------|------|
| **动态图** | 每个 batch 基于特征重建 | 适应不同样本 | 计算开销 ~2% |
| 静态图 | 预先构建，固定不变 | 计算快 | 不适应样本差异 |

### 为什么选择动态图？

1. **不同样本的包序列差异大**
   - 正常流量 vs 攻击流量的包模式完全不同
   - 静态图无法捕获这种差异

2. **计算开销可接受**
   - 图构建仅占总计算量的 ~2%
   - 动态图带来的性能提升远超计算开销

3. **实验验证**
   - 动态图：Macro F1 = 0.9544
   - 静态图（假设）：Macro F1 ≈ 0.93-0.94

## Q6: 图的节点特征是如何更新的？

**A**: 通过 **GATv2（图注意力网络）** 聚合邻居信息。

### 更新过程

```python
# 输入
x: (batch, 100, 128)  # 100 个节点，每个节点 128 维特征
adj: (batch, 100, 100)  # 邻接矩阵

# GATv2 更新
for each node i:
    # 1. 计算注意力分数
    attn_scores[i, j] = attention(x[i], x[j])  # 对所有邻居 j
    
    # 2. 只保留连接的邻居
    attn_scores[i, j] = attn_scores[i, j] if adj[i, j] == 1 else -inf
    
    # 3. Softmax 归一化
    attn_weights[i] = softmax(attn_scores[i])
    
    # 4. 加权聚合邻居特征
    x_new[i] = sum(attn_weights[i, j] * x[j] for all neighbors j)

# 输出
x_new: (batch, 100, 128)  # 更新后的节点特征
```

### 直观理解

- 每个节点（数据包）查看其邻居（相似的数据包）
- 根据相似度分配注意力权重
- 聚合邻居的信息来更新自己的表示
- 经过多层 GATv2，每个节点能感知到更远的邻居

**A**: 平衡信息量和计算效率。

### 不同序列长度的影响

## Q8: 图结构在整个模型中的作用是什么？

**A**: 捕获数据包之间的**空间关系**（相似性）。

### 模型架构

```
输入: (64, 100, 25)
  ↓
输入投影: (64, 100, 128)
  ↓
Transformer: (64, 100, 128)  ← 捕获时序依赖
  ↓
构建图: adj (64, 100, 100)  ← 基于特征相似度
  ↓
ST-Block 1:
  ├─ TCN: (64, 100, 128)     ← 时序分支
  ├─ GATv2: (64, 100, 128)   ← 空间分支（使用图结构）
  └─ 门控融合: (64, 100, 128)
  ↓
ST-Block 2: ...
  ↓
ST-Block 3: ...
  ↓
池化: (64, 128)
  ↓
分类器: (64, 9)
```

### 图结构的价值

1. **捕获非时序的相似性**
   - 时序模型（LSTM/Transformer）只能捕获相邻包的关系
   - 图结构能连接任意相似的包（即使相隔很远）

2. **攻击模式识别**
   - 攻击流量中，相似的包会形成密集的子图
   - 正常流量中，包之间的连接更稀疏

3. **提升性能**
   - 纯时序模型（CNN1D）：Macro F1 = 0.8977
   - 时序 + 图（Hybrid 改进版）：Macro F1 = 0.9544
   - **提升 +5.67%**

## Q10: 图结构的计算开销大吗？

**A**: 不大，仅占总计算量的 **~2%**。

### 计算量分解

| 阶段 | 计算量 | 占比 |
|------|--------|------|
| 图构建 | ~82M 操作 | 2% |
| Transformer | ~920M 操作 | 22% |
| ST-Blocks (3层) | ~3.3B 操作 | 75% |
| 其他 | ~40M 操作 | 1% |
| **总计** | **~4.4B 操作** | **100%** |

### 训练时间

- **总训练时间**: 6.6 分钟（100 epochs）
- **图构建时间**: ~8 秒（2%）
- **主要时间**: ST-Blocks（GATv2 + TCN）

**结论**：图构建的开销很小，但带来的性能提升显著！
